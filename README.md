# Task Tracker

Внутренний веб-сервис для постановки, выполнения, проверки и контроля задач небольшого отдела.

Текущая версия: **0.19.9** (источник версии — файл [`VERSION`](VERSION))

Изменения этой версии: [RELEASE_NOTES_0.19.9.md](RELEASE_NOTES_0.19.9.md).

Проект рассчитан примерно на 15 пользователей и разворачивается на Raspberry Pi 5 через Docker Compose.

## Возможности

### Работа с задачами

- создание и назначение задач руководителем;
- приоритеты и трудоёмкость;
- плановое начало и срок;
- быстрые действия по статусам;
- комментарии;
- фото и скриншоты;
- история изменений;
- фактическое время начала, отправки на проверку и завершения;
- календарь;
- Kanban;
- фильтры и сортировка;
- быстрый фильтр задач со сроком в ближайшие 7 дней;
- метки проектов: менеджер может добавить название проекта (например, `1202.55 ООО Ачимгаз`), затем выбирать его из списка и фильтровать задачи;
- персональные сохранённые фильтры для каждого пользователя;
- глобальный поиск по номеру, названию, описанию, сотруднику, руководителю и комментариям;
- массовое изменение исполнителя, ответственного руководителя, приоритета и срока;
- номера задач вида `#123`.

### Workflow

```text
Новая
  ↓
В работе
  ↓
На проверке
  ├── Принять → Выполнена
  └── Вернуть → На доработке
                  ↓
               В работе
```

Руководитель также может самостоятельно перевести задачу в `Выполнена`.

### Для руководителя

- общий список задач;
- дашборд;
- очередь «Ожидают проверки»;
- загрузка сотрудников;
- календарь;
- аналитика;
- Activity feed;
- шаблоны задач;
- учёт отсутствий сотрудников.

### Для сотрудника

- только назначенные ему задачи;
- «Мои задачи на сегодня»;
- начало работы;
- отправка на проверку;
- получение уведомлений о принятии/доработке;
- комментарии;
- загрузка фото и скриншотов.

## Быстрый запуск

Создайте `.env` на основе `.env.example`:

```bash
cp .env.example .env
```

Заполните реальные секреты, затем:

```bash
docker compose up -d --build
```

Проверка:

```bash
docker compose ps
curl http://127.0.0.1:8081/health/
```

Миграции выполняются автоматически контейнером `web`.

## Роли

Используются стандартные Django `User` и `Group`.

### Managers

Руководители:

- видят все задачи отдела;
- создают задачи;
- каждая задача имеет отдельного ответственного руководителя;
- изменять, проверять и закрывать задачу может её ответственный руководитель (superuser остаётся административным исключением);
- ответственный может передать задачу другому руководителю;
- для своих задач изменяет исполнителя, приоритеты и сроки;
- принимают выполненные задачи;
- возвращают свои задачи на доработку;
- имеют доступ к аналитике и загрузке сотрудников.

### Employees

Сотрудники:

- видят только свои задачи;
- переводят `Новая → В работе`;
- отправляют выполненную работу на проверку;
- работают с комментариями и изображениями в доступных им задачах.

Подробнее: [docs/roles.md](docs/roles.md).

## Изображения

К задаче можно прикреплять только изображения:

- JPEG;
- PNG;
- WebP.

Изображения сохраняются в отдельном Docker volume и выдаются только после проверки прав доступа пользователя.

## CI/CD

При push в `main` GitHub Actions:

1. устанавливает зависимости;
2. выполняет Django system check;
3. проверяет миграции;
4. запускает pytest;
5. на self-hosted runner создаёт backup;
6. собирает Docker images;
7. обновляет production;
8. проверяет `/health/`.

Подробнее: [docs/deployment.md](docs/deployment.md).

## Backup

Перед production deploy автоматически создаётся переносимый host-backup **вне Docker volumes**. В один архив входят:

- PostgreSQL dump;
- пользовательские изображения;
- manifest с версией и commit.

На Raspberry Pi backup по умолчанию хранится в `~/projects/backups/task-tracker/`.

Для тестового запуска через Docker Desktop на Windows добавлены:

```powershell
.\scripts\backup_windows.ps1
.\scripts\install_backup_task_windows.ps1
```

Windows-копии сохраняются на диск хоста вне Docker volumes и могут быть перенесены на флешку.

Подробнее: [docs/backup_restore.md](docs/backup_restore.md).
