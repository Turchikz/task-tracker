# RaTracker v0.9.0 — совместная работа и контроль отдела

## Основные изменения

1. **Исправление формы исполнителей.** В списке «Дополнительные исполнители» основной сотрудник автоматически исключается и на сервере, и в интерфейсе при смене выбранного основного исполнителя. Существующие данные не удаляются.
2. **Умное распределение при отсутствии.** На странице «Отсутствия» появился список затронутых задач с кандидатами на замену, упорядоченными по текущей загрузке. Учитываются пересекающиеся периоды отсутствий и участие в команде. Руководитель вручную подтверждает замену. Поддерживаются основной и дополнительный исполнитель. Сроки, задача и её история сохраняются. Рекомендации не являются автопередачей.
3. **Готовность участников.** В карточке общей задачи каждый соисполнитель может отдельно отметить «Не приступил», «В работе» или «Готово». Руководитель видит всех участников и их состояния. Общий статус задачи и старая процедура проверки не меняются.
4. **Экспорт Excel.** На странице «Аналитика» кнопка выгрузки `.xlsx` с листами «Обзор», «Сотрудники», «Задачи», «Текущая загрузка». Защитные меры: только для Managers, пользовательские строки записываются как текст, а не формулы.
5. **Контроль backup.** В меню администратора открывается страница последней резервной копии. Скрипты Windows/Linux записывают только публичные метаданные в `backup_status/backup_status.json`. В контейнер папка монтируется только на чтение. **Сам архив, `.env` и секреты не попадают в веб-контейнер.** Доступ к экрану — только суперпользователю. Устаревший backup (>36 ч) и backup без медиа обозначаются предупреждением.
6. **Цветная загрузка.** В рейтинге загрузки, форме задачи и на странице «Загрузка» появились индикаторы. На дашборде руководителя — отдельная семидневная тепловая карта. Цвета обозначают условные баллы (1–7 низкая, 8–19 умеренная, 20+ высокая), не фактические часы или оценку сотрудников.
7. **Аватары участников.** Стек инициалов до четырёх сотрудников и счётчик остальных в таблице, канбане, карточке задачи и «Сегодня». Полные имена сохранены в подсказках и карточке.
8. **Центр уведомлений.** Колокольчик открывает панель справа, не меняя страницу. Видны последние семь уведомлений, есть кнопка «Прочитано» и ссылка на полную историю. Клавиатура: Escape и удержание фокуса внутри панели.

## Что осталось прежним

- Схема владения задачей через `responsible_manager`.
- Старые задачи и их история; файловые вложения.
- Массовые действия, персональные фильтры и поисковая строка.
- Наглядная таблица нагрузки сотрудников **в форме задачи**, предназначенная для демонстрации руководству.
- Docker Compose, ежедневные backup вне Docker, светлая/тёмная тема, лампочка и кнопка выхода.

## Миграции

Новая миграция: `tasks/migrations/0009_member_progress.py`.

Для существующих задач создаются записи готовности основных и дополнительных исполнителей со статусом «Не приступил». Вторая связь исполнителей и история передач остаются без изменений.

## Обновление тестового проекта (Windows / Docker Desktop)

1. Сохранить резервную копию:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\backup_windows.ps1
```

2. Распаковать **полный проект** поверх текущего проекта, не перезаписывая настоящий `.env`.

3. Выполнить:

```powershell
docker compose up -d --build
docker compose exec web python manage.py migrate
docker compose exec web python manage.py check
docker compose exec web pytest tests/test_v090_features.py
docker compose exec web pytest
```

4. Обновить страницу через `Ctrl + F5`.

5. Запустить один свежий backup и проверить **Администрирование → Резервные копии** (пункт появляется в меню профиля суперпользователя). До первого backup с новым скриптом мониторинг показывает «Нет сведений».

`backup_status/` — служебная папка внутри каталога проекта, **а не место хранения архивов**. Архивы по-прежнему записываются на диск Windows или Raspberry Pi за пределами контейнеров.

## Техническая проверка

Архив собран со статической проверкой Python и JavaScript; добавлены тесты на форму, совместные задачи, отсутствие, Excel, права и метаданные backup. Для полной интеграционной проверки необходимо выполнить `pytest` внутри Docker, где установлены Django-зависимости и PostgreSQL.
