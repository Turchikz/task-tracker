# Роли и права

Проект использует стандартную модель Django:

```text
User
Group
Permissions
```

Пользовательская модель ролей не создаётся.

Основные группы:

```text
Managers
Employees
```

## Managers

Руководитель видит все задачи отдела, но изменяет только задачи, где он указан как `Task.responsible_manager`. `Task.created_by` хранит автора и не меняется при передаче ответственности.

Для собственных задач может:

- создавать задачу;
- назначать исполнителя;
- переназначать исполнителя;
- менять сроки;
- менять приоритет;
- менять трудоёмкость;
- принимать задачу;
- возвращать на доработку;
- самостоятельно завершать задачу;
- отменять задачу;
- видеть загрузку сотрудников;
- видеть аналитику;
- управлять шаблонами;
- работать с отсутствиями.

Задачи другого ответственного руководителя доступны Manager только для просмотра. Уведомление о результате и очередь проверки получает только текущий `responsible_manager`. `superuser` остаётся административным исключением.

## Employees

Сотрудник видит только назначенные ему задачи.

Может:

- открыть собственную задачу;
- перевести `Новая → В работе`;
- отправить работу на проверку;
- повторно начать задачу после возврата;
- добавлять комментарии;
- добавлять разрешённые изображения.

Не может:

- создавать задачи;
- видеть задачи других сотрудников;
- самостоятельно финально принимать свою задачу;
- менять исполнителя;
- менять срок;
- менять приоритет;
- смотреть manager-only аналитику.

## Проверки прав

Права должны проверяться сервером.

Скрытие кнопки в HTML не является механизмом безопасности.

Любое действие, доступное только руководителю, должно дополнительно проверять группу пользователя во view/service.


## Ответственный руководитель (v0.7.0)

`Task.created_by` хранит автора задачи и не меняется.

`Task.responsible_manager` определяет текущего владельца управленческого workflow:

- редактирование управленческих полей;
- «Принять в работу»;
- окончательное принятие результата;
- возврат на доработку;
- массовые изменения;
- получение уведомления «На проверке».

Другие Managers сохраняют право просмотра задачи, но не управления ею. Superuser имеет административный override. При миграции существующим задачам ответственный руководитель назначается равным их автору.


## Работа команды (v0.8.3)

- `Task.assigned_to` — основной исполнитель.
- `Task.additional_assignees` — дополнительные исполнители с теми же правами
  на работу по задаче, комментарии и вложения.
- Все исполнители используют общий статус; только ответственный руководитель
  может принять, завершить или вернуть на доработку.
- Передача задачи записывается в `TaskHandover` и `TaskEvent`.
