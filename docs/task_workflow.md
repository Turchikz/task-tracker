# Workflow задач

## Проектные метки

Руководитель может указать в задаче одну или несколько меток, например название
проекта `1202.55 ООО Ачимгаз`. Новая метка создаётся при первом сохранении;
затем она предлагается в списке при вводе. Метки общие для отдела и доступны
для фильтрации списка задач. Исполнитель может просматривать метки назначенной
задачи, но не управляет справочником меток.

## Основной жизненный цикл

```text
Новая
  ↓
В работе
  ↓
На проверке
  ├── руководитель принимает → Выполнена
  └── руководитель отклоняет → На доработке
                               ↓
                            В работе
                               ↓
                            На проверке
```

Дополнительный конечный статус:

```text
Отменена
```

## Новая

Задача создана, но сотрудник ещё не приступил к работе.

Исполнитель может перевести её в `В работе`.

## В работе

Исполнитель приступил к выполнению.

При первом таком переходе фиксируется фактическое время начала работы.

После завершения исполнитель отправляет результат на проверку.

## На проверке

Работа исполнителя временно завершена.

Система:

- фиксирует время отправки;
- уведомляет ответственного руководителя;
- показывает задачу в очереди проверки.

На этом этапе задача не увеличивает текущую рабочую нагрузку исполнителя.

## На доработке

Руководитель не принимает результат.

Причина возврата обязательна.

Исполнитель:

1. получает уведомление;
2. видит причину;
3. продолжает работу;
4. повторно отправляет задачу на проверку.

## Выполнена

Финальное состояние задачи.

Обычно устанавливается после принятия результата руководителем.

Руководитель также может самостоятельно отметить задачу выполненной.

## Отменена

Работа по задаче прекращена.

Отменённая задача не входит в текущую загрузку.

## История

Каждый значимый переход фиксируется в истории задачи.

История предназначена для ответа на вопросы:

- кто изменил задачу;
- когда изменился статус;
- когда изменился срок;
- почему работа была возвращена;
- когда задача была окончательно принята.

## Несколько исполнителей (v0.8.3)

У задачи есть основной исполнитель и дополнительные соисполнители. Все они
работают с **общим статусом** задачи. Ответственный руководитель принимает
общий результат. Одна карточка задачи видна у каждого участника в разделах
«Сегодня» и «Загрузка».

## Передача задачи при отсутствии сотрудника

Руководитель может передать активную задачу другому основному исполнителю с
обязательной причиной. Передача не сбрасывает данные и сроки задачи. Сведения
о предыдущем исполнителе сохраняются в отдельной истории передач, а прежнему
можно оставить роль соисполнителя.

Подробнее: `docs/collaboration_and_handover.md`.
