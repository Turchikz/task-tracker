# v0.9.0 — режимы и ограничения

## Перераспределение задач

На вкладке **Отсутствия** система показывает открытые задачи, у которых планируемая работа пересекается с периодом недоступности назначенного исполнителя. Задачи иных руководителей остаются только для просмотра, и поэтому не включены в список автоматических предложений на передачу.

Система сортирует доступных сотрудников по текущему показателю загрузки и исключает участников, которые уже назначены на данную задачу, а также сотрудников с пересекающимся отсутствием. Кандидат предложен, но ничего не передаётся без подтверждения менеджером.

При замене основного исполнителя используется прежний механизм `transfer_primary_assignee`. При замене дополнительного — `replace_additional_assignee`, не затрагивающий основной FK `assigned_to`. Обе операции регистрируют запись в `TaskHandover`. Старые фотографии, комментарии и исходная задача остаются.

## Готовность соисполнителей

`TaskMemberProgress` хранит состояние каждого сотрудника. Миграция создаёт начальные записи для действующих участников существующих задач; новые записи добавляются сигналами создания задачи и включения участника.

Состояния `pending/in_progress/ready` **не являются** статусом общей задачи и не блокируют действия v0.8.3. Изменения состояния также отображаются в истории задачи. При возвращении задачи на доработку готовность текущих исполнителей сбрасывается в «В работе».

## Excel

Экспорт использует библиотеку `XlsxWriter` в Docker-образе. Выгружается одна книга с несколькими листами за указанный период. Пользовательские строки всегда записываются как строки; вычисляемые ячейки не создаются.

## Контроль backup

Скрипты backup записывают итог в `<каталог проекта>/backup_status/backup_status.json`. Файл содержит время, имя архива, размер, SHA-256 и наличие media, **без пути к приватным копиям и без паролей**. Контейнер видит эту папку только для чтения по пути `/app/backup_status`.

Эта индикация показывает факт созданного файла и его checksum, но **не является подтверждением успешного восстановления**. Для полного контроля нужно периодически восстанавливать резервную копию на отдельной тестовой базе.
